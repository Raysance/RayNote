# 技术说明

## 运行结构

当前实现复用本地 Raycast 1.104.31 的原生 Notes 模块和原版 Web 编辑器，由新增 Objective-C 宿主独立启动。仓库提供宿主、提取脚本和验证工具，没有恢复或包含原始 Swift 工程。

提取过程将原可执行文件转换为可加载的 `MH_BUNDLE`，保留原代码和数据布局，调整加载命令与 chained fixups。运行时通过 `dlopen` 加载 `RaycastCore`，初始化原版 Application、Notes 窗口、控制器、主题提供器和所需服务，跳过完整启动器的启动流程。

原版二进制仍包含其他静态链接代码；没有将每一段无关机器码物理移除。宿主只启动 Notes 所需路径。

## 宿主适配

| 文件 | 用途 |
| --- | --- |
| `extract.py` | 复制资源、转换模块、应用固定地址修改、编译和签名 |
| `native_main.m` | 原生模块启动、主题初始化、目录隔离与网络限制 |
| `gui_support.h` | 应用生命周期、菜单与事件适配 |
| `native_settings.h` | 原版 Notes 设置提供器、列表容器与菜单栏入口 |
| `credentials.m` | 独立生成的数据库和缓存密钥持久化 |
| `security_slots.h` | 原模块四个 Security 导入槽的地址 |
| `swift_bridge.S` | 带 Swift 上下文寄存器的内部函数调用桥 |
| `verify.py` | 指令、资源、哈希与签名校验 |

机器码清单共有 11 处修改，涉及 Notes 的本地数量限制、对应只读和升级分支，以及独立设置窗口入口。没有模拟服务器授权或解锁远端服务。

## 存储与网络

应用使用独立目录和新建的加密数据库，不读取原应用的笔记或系统钥匙串。四个 Security 导入调用适配为本地凭据文件，仅处理独立应用生成的数据库、缓存密钥。文件权限为 `0600`，数据目录为 `0700`。

该密钥文件没有系统钥匙串的访问保护，同一用户权限下的其他程序可能读取它。备份必须包含密钥和数据库。损坏或缺失密钥时拒绝启动，以避免生成新密钥覆盖旧数据。

宿主应用进程禁止网络访问，并禁止读写原 Raycast 数据目录及写入原应用。云同步和 AI 不可用。

## 验证和边界

39,207,872 字节原生代码除清单记录的修改外与输入二进制一致，编辑器 HTML、JS、CSS 和字体资源逐文件一致。实际验证包括八条笔记、较早笔记仍可编辑、中文保存、正常和快速退出后恢复、查找、Markdown 导出和 Notes 设置。

原 Raycast 主进程挂起时，独立应用仍成功新建和编辑笔记。运行时加载的核心和附加框架来自独立应用自身。

尚未完整迁移或验证启动器的全局快捷键、Quicklinks、深链接，以及所有边界行为和长期稳定性。应用生命周期和部分事件处理由宿主接管，不能据此宣称整个原应用的行为完全相同。

内部函数地址与指定输入构建绑定，后续升级需要重新分析和验证。当前构建仅在本机 arm64 macOS 27.0.1 实测。

之前的 SwiftUI 实现在 Git 历史中保留；它的 JSON 笔记和备份机制不适用于当前实现，也没有自动迁移程序。
